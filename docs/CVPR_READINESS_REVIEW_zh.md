# CVPR 投稿准备度评估（2026-11-03）

## 结论

**当前版本：不建议按现状投稿；属于有真实实验基础、但核心论证仍有重大缺口的稿件。** 真机结果是一个显眼缺项，但即使同事补齐，本文的任务判据、方法贡献归因和系统比较仍需先处理。基于现有材料，我会把当前版本估在 **weak reject / borderline reject**，不是对真实 CVPR 评审结果的预测保证。信心：中等；本文领域匹配，但相关工作和部分算法实现还需独立核验。

有价值的基础是：多对象仿真规模实际（六种对象、对象专属发布、两种映射）；记录保留原始 40-trial 条件、失败与服务排除；反馈图像干预在匹配初态上的差异较大；论文对控制无显著收益、失败案例和仿真局限已有不少诚实披露。当前可稳妥支持的主结论是：**在给定系统和立方体任务中，重复获得当前图像比反复使用初始图像得到更高完成率；完整系统在若干对象的改变映射任务上取得较高的观测完成率。** 证据不能支持 learned waiting controller 优于 fixed slowing，也不能支持跨对象零样本迁移、实时硬件能力或单独归因于 VLM。

## 主要问题（按投稿风险排序）

### 1. 任务语言与主成功判据不匹配：重大

[03_task.tex](/home/yin/DexManipulation/agentic-inhand-manipulation/agent-inhand-manipulation/outputs/reveal_cvpr_final_20261103/sections/03_task.tex) 明确承认：指令只要求字母面朝上，主指标却要求完整 canonical quaternion 在 0.16 rad 内，额外限定了指令未指定的面内 twist。对“正确地呈现指定面”而言，这会把任务定义改变成更强的、用户没有要求的姿态任务，且可能将语义正确但 twist 不同的结果算失败。这是主结果有效性问题，不能只作为措辞限制。

投稿前必须从保留的终态姿态重算**面法向误差**（例如目标面法线和世界竖直方向夹角），并同时给出语义绑定、面法向达标、canonical 完整姿态三项指标。若系统确实需要特定 twist 才能稳定呈现，应修改任务指令并解释其必要性，再核实所有策略训练目标、停止器和测试记录与此定义一致。报告新旧两种标准下的分歧 trial，不能只把更有利的一项替换成主指标。

### 2. 方法新颖性尚未从系统集成中分离出来：重大

当前贡献是异步视觉 agent、已有 recurrent pose policy、语义 goal bank、teacher-supervised waiting/execution residual controller 的组合。正文自己承认 residual learning 不是新颖性主张；Q2 又没有确认 learned waiting 优于固定减速。Q3 有清楚的当前图像干预结果，但并未检验所提 controller 或共享语义 latent 是否是该收益来源。Related Work 已列出实时 action chunking、在线纠正、延迟鲁棒 VLA 和异步灵巧控制，因而“在推理等待时继续控制”本身不能独立承担新颖性。

必须用一项**针对方法核心、训练与计算量匹配的消融**建立增量：例如相同视觉策略/模型调用下比较固定减速、通用 time-aware reactive residual、以及本文 goal/request-anchor-conditioned controller；使用同样训练预算、同一学生与物理初态，跨至少 cube 与一个几何不同对象，按配对结果报告完成、掉落和等待阶段失败。否则应把论文定位为有用的完整系统/数据实证，并避免把控制器描述为已验证的性能贡献。

### 3. Q1 是异构的完整系统比较，不能回答模型或共享方法的因果优势：重大

[05_experiments.tex](/home/yin/DexManipulation/agentic-inhand-manipulation/agent-inhand-manipulation/outputs/reveal_cvpr_final_20261103/sections/05_experiments.tex) 已说明 Astra 有历史、探测和自适应反馈；裸 baseline 使用固定不可读调度，且没有新增 waiting/execution actor。Q1 的六个对象也各自使用 motor/perception release；cube 使用 RGB pose，其他对象使用 noisy simulator pose。因此这组数据可用于描述**这些完整配置**，不能归因于 agent 模型、控制器或某个共同策略。各新对象 40 次/格、两随机种子，足以显示大差异，但不足以证明稳定泛化；milk carton 改映射只有 11/40，原映射 17/40，失败率也揭示系统脆弱。

最低限度应增加 shared-backend 对照：对比时给所有语义方法相同的学生、传感输入、控制器、停止器和可比较的视觉调用预算；单独列出完整 REVEAL 系统与裸模型的生态比较，并明确其非因果性质。对象结果逐对象报告，不对异构 backend 做总平均。增加新对象时，明确是新资产/新策略适配后的能力，不能称为零样本迁移。

### 4. 控制部分的统计结论是“不确定”，需继续保持克制：中高风险

Q2 的 34/40（full）点估计看起来高于 fixed slowing 30/40；但注册配对对比 Holm 校正后 $p=.539$。独立确认反而是 learned full 30/39、fixed 31/39，配对 Holm $p=1.0$；full 有 8 次 execution drop，fixed 有 3 次。当前稿件已正确写成“未建立 learned-control advantage”。不要在摘要、贡献或图示中重新包装为成功率提升。若把控制器作为主要贡献，需要先有更高功效、预先定义终点且跨场景的确认实验；否则把它写成一种实现/设计探索，并报告负结果。

### 5. 反馈证据强，但应准确限定效应范围：中风险

同调用上限的图像实验为 current RGB 32/40 对重复初帧 9/40，23 对不一致配对全部支持 current RGB（精确配对检验 Holm $p=4.77\times10^{-7}$）。这是全稿最干净的机制证据。它证明的是**在本系统其余反馈和控制保持开启时，向上层 agent 提供更新 RGB 的效果**；不是等实际 compute（112 对 98 calls）、轨迹、延迟或调用次数的比较，也不是“持续反馈必然帮助所有对象”。主张保持在立方体与该协议内。另一组单次计划对多次反馈同时改变推理预算（6/39 对 33/39），只适合作为系统协议比较。

### 6. 真机结果需要作为独立、可审计的实验包：重大投稿缺项

当前 Q4 是 TODO，不是真机结果。新增结果至少应有：明确的实际物体和映射、成功判据的外部/独立评分、固定相机与手部校准、所有成功/失败与掉落、同步视频/动作/agent 日志、重置及操作者说明、延迟和 wall-clock 控制频率，并保留原始试次而不挑选展示。若要比较系统，应在同一真机后端上测试全部方法，采用匹配条件/随机顺序并报告每物体结果。若同事只提供漂亮案例视频或没有对照的小样本演示，它能证明可运行性，不能支撑“works on physical objects”的比较结论。

当前仿真逻辑 30 Hz、但仿真慢于实时；不能据此声称系统能以 30 Hz 在真机持续执行。主文还需把仿真逻辑时钟和实际推理等待/真实控制率区分开。

## 次级但重要的修订

- **基线公平性：** 把两种结果类型分表或分段：matched-backend 方法消融与完整系统生态比较。报告每个 baseline 实际收到的图像、历史、调用数、控制模块和停止逻辑。尤其 dice 对 Astra 使用额外探测/完成校正，而两个 bare VLM 没有。
- **映射干预范围：** cube 使用重建图像，die 旋转纹理 mesh，新增对象置换表面字母；这不是一种统一干预。分别命名为不同 layout/semantic intervention，别用单个泛化概念遮盖协议差异。
- **小样本不确定性：** 每格 40 次、两个种子，报告配对效应量与区间（适用时按环境 seed 聚类）；在表或附录给每格区间。不得以某条件显著、另一条件不显著来声称两系统等价。
- **位姿研究定位：** 64.73% RGB-D 对 37.53% RGB 的支持评估用理想目标 mask 与虚拟深度，且 checkpoint 不同；它不是主系统 predictor 的替换实验，也不说明闭环成功或真机视觉改进。现有限制已相当透明，摘要不要突出这项数字。
- **文献核验：** 当前 references 数量少，且几条 2026 年 arXiv 条目需要逐条核对标题、作者、日期、论文是否确实存在，以及正文主张是否由引用支持。本文这次尝试在线检索时，搜索连接器因账户 OAuth token revoked 返回 401；所以我没有把引用称作已核实。投稿前需用官方论文页/arXiv/会议 proceedings 完成引用存在性和最近相关工作的核查。
- **图示/方法一致性：** v4 图中的 State MSE、State decoder 与主文简写的 DAgger action fitting 并不完全对应。应核对代码与训练 manifest：若 state auxiliary loss 实际启用，在 Method 与补充材料给出定义、权重、监督信息和训练阶段；若未启用，从图里删掉。图中的物理图片区域已改为 TODO，正式插入真机图片后再去除占位标识。
- **限制与复现：** 补齐托管模型服务 revision、sampling 配置及去敏 prompt/action schema；保存所有发布的权重、pose/calibration、对象资产、归一化和仿真版本。论文已披露 hosted-model revision 会影响复现，这一点仍需落实为可用材料。
